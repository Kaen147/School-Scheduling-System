## 📖 What is Object-Oriented Programming?

OOP is a programming paradigm (way of thinking about code) that organizes software around **objects** rather than functions and logic.

### Real-World Analogy

Think about a car:
- **Properties (Data):** color, brand, speed, fuel level
- **Methods (Behavior):** start(), accelerate(), brake(), refuel()

In OOP, we model our code the same way - grouping related data and behavior together.

```javascript
// A car as an object
const car = {
  // Properties (what it HAS)
  brand: "Toyota",
  color: "blue",
  speed: 0,
  fuelLevel: 100,
  
  // Methods (what it DOES)
  start() {
    console.log("Engine started!");
  },
  
  accelerate() {
    this.speed += 10;
    this.fuelLevel -= 5;
    console.log(`Speed: ${this.speed} km/h`);
  },
  
  brake() {
    this.speed = Math.max(0, this.speed - 10);
    console.log(`Speed: ${this.speed} km/h`);
  }
};
```

## 🆚 Procedural vs Object-Oriented

### Procedural Approach

Data and functions are separate. Functions operate on data passed to them.

```javascript
// Data
const user1 = { name: "John", balance: 100 };
const user2 = { name: "Jane", balance: 200 };

// Functions that operate on data
function deposit(user, amount) {
  user.balance += amount;
}

function withdraw(user, amount) {
  if (user.balance >= amount) {
    user.balance -= amount;
    return true;
  }
  return false;
}

function transfer(from, to, amount) {
  if (withdraw(from, amount)) {
    deposit(to, amount);
    return true;
  }
  return false;
}

// Usage
deposit(user1, 50);
transfer(user1, user2, 30);
```

**Problems:**
- Data can be modified from anywhere
- Functions are scattered, hard to find related ones
- No clear ownership of data

### Object-Oriented Approach

Data and behavior are bundled together in objects.

```javascript
class BankAccount {
  constructor(owner, initialBalance = 0) {
    this.owner = owner;
    this.balance = initialBalance;
  }
  
  deposit(amount) {
    if (amount > 0) {
      this.balance += amount;
      return true;
    }
    return false;
  }
  
  withdraw(amount) {
    if (amount > 0 && this.balance >= amount) {
      this.balance -= amount;
      return true;
    }
    return false;
  }
  
  transfer(toAccount, amount) {
    if (this.withdraw(amount)) {
      toAccount.deposit(amount);
      return true;
    }
    return false;
  }
  
  getBalance() {
    return this.balance;
  }
}

// Usage
const account1 = new BankAccount("John", 100);
const account2 = new BankAccount("Jane", 200);

account1.deposit(50);
account1.transfer(account2, 30);
```

**Benefits:**
- Data and behavior are together
- Clear ownership and responsibility
- Easier to understand and maintain
- Can create multiple instances easily

## 🏛️ The Four Pillars of OOP

### 1. Encapsulation
**Bundle data and methods together, hide internal details.**

```javascript
class User {
  #password;  // Private - hidden from outside
  
  constructor(name, password) {
    this.name = name;
    this.#password = this.#hashPassword(password);
  }
  
  #hashPassword(password) {  // Private method
    return `hashed_${password}`;
  }
  
  checkPassword(input) {
    return this.#password === this.#hashPassword(input);
  }
}

const user = new User("John", "secret123");
console.log(user.name);           // "John" - public
console.log(user.#password);      // Error! - private
console.log(user.checkPassword("secret123"));  // true
```

### 2. Inheritance
**Create new classes based on existing ones.**

```javascript
class Animal {
  constructor(name) {
    this.name = name;
  }
  
  speak() {
    console.log(`${this.name} makes a sound`);
  }
}

class Dog extends Animal {
  speak() {
    console.log(`${this.name} barks!`);
  }
  
  fetch() {
    console.log(`${this.name} fetches the ball`);
  }
}

const dog = new Dog("Buddy");
dog.speak();  // "Buddy barks!"
dog.fetch();  // "Buddy fetches the ball"
```

### 3. Polymorphism
**Same interface, different implementations.**

```javascript
class Shape {
  area() {
    return 0;
  }
}

class Rectangle extends Shape {
  constructor(width, height) {
    super();
    this.width = width;
    this.height = height;
  }
  
  area() {
    return this.width * this.height;
  }
}

class Circle extends Shape {
  constructor(radius) {
    super();
    this.radius = radius;
  }
  
  area() {
    return Math.PI * this.radius ** 2;
  }
}

// Same method call, different behavior
const shapes = [new Rectangle(4, 5), new Circle(3)];
shapes.forEach(shape => console.log(shape.area()));
// 20, 28.27...
```

### 4. Abstraction
**Hide complexity, show only what's necessary.**

```javascript
class EmailService {
  send(to, subject, body) {
    // User only needs to know about this method
    this.#validate(to);
    this.#connect();
    this.#transmit(to, subject, body);
    this.#disconnect();
    return true;
  }
  
  // Complex implementation hidden
  #validate(email) { /* ... */ }
  #connect() { /* ... */ }
  #transmit(to, subject, body) { /* ... */ }
  #disconnect() { /* ... */ }
}

// Simple to use!
const email = new EmailService();
email.send("user@example.com", "Hello", "How are you?");
```

## 🎯 Key OOP Concepts

### Class
A blueprint for creating objects.

```javascript
class Car {
  constructor(brand, color) {
    this.brand = brand;
    this.color = color;
  }
}
```

### Object (Instance)
A specific thing created from a class.

```javascript
const myCar = new Car("Toyota", "blue");
const yourCar = new Car("Honda", "red");
// Two different objects from the same class
```

### Constructor
Special method that runs when creating an object.

```javascript
class User {
  constructor(name, email) {
    this.name = name;
    this.email = email;
    this.createdAt = new Date();
  }
}
```

### this Keyword
Refers to the current object instance.

```javascript
class Counter {
  constructor() {
    this.count = 0;
  }
  
  increment() {
    this.count++;  // 'this' refers to the counter instance
    return this;   // Return this for chaining
  }
}

const counter = new Counter();
counter.increment().increment().increment();
console.log(counter.count);  // 3
```

## 🤔 When to Use OOP

### Good Use Cases

1. **Modeling real-world entities**
   - Users, Products, Orders, Accounts

2. **When you need multiple similar objects**
   - Game characters, UI components, data records

3. **When data and behavior are closely related**
   - A User has methods like login(), updateProfile()

4. **When you need to extend functionality**
   - Base class with specialized subclasses

### When NOT to Use OOP

1. **Simple scripts or utilities**
   - A function that formats dates doesn't need a class

2. **Stateless operations**
   - Pure functions that just transform data

3. **When it adds unnecessary complexity**
   - Don't create a class for one simple object

## 💡 OOP Design Thinking

### Step 1: Identify the Nouns (Objects)

"A **library** has **books** that **members** can borrow."

Objects: Library, Book, Member

### Step 2: Identify Properties (What They Have)

- Book: title, author, isbn, isAvailable
- Member: name, memberId, borrowedBooks
- Library: books, members

### Step 3: Identify Methods (What They Do)

- Book: checkOut(), return()
- Member: borrow(), returnBook()
- Library: addBook(), registerMember(), findBook()

### Step 4: Identify Relationships

- Library HAS many Books (composition)
- Library HAS many Members (composition)
- Member HAS many borrowed Books (association)

  todoList.push({ id: nextId++, title, completed: false });
}

function completeTodo(id) {
  const todo = todoList.find(t => t.id === id);
  if (todo) todo.completed = true;

function removeTodo(id) {
  todoList = todoList.filter(t => t.id !== id);

## 🎯 Summary

- **OOP** organizes code around objects that combine data and behavior
- **Four Pillars:** Encapsulation, Inheritance, Polymorphism, Abstraction
- **Classes** are blueprints, **objects** are instances
- **constructor** initializes new objects
- **this** refers to the current instance
- Think in terms of nouns (objects) and verbs (methods)
- Use OOP when modeling real-world entities or creating multiple similar objects
