## 📖 The Client-Server Model

### What Happens When You Visit a Website?

```
1. You type "google.com" in browser
2. Browser asks DNS: "What's the IP for google.com?"
3. DNS responds: "142.250.185.78"
4. Browser connects to that IP address
5. Browser sends HTTP request: "GET / HTTP/1.1"
6. Server processes request
7. Server sends HTTP response with HTML
8. Browser renders the HTML
```

### Client vs Server

```
┌─────────────┐                    ┌─────────────┐
│   CLIENT    │                    │   SERVER    │
│  (Browser)  │                    │  (Backend)  │
│             │                    │             │
│  - React    │  ── Request ──>    │  - Express  │
│  - Vue      │                    │  - Node.js  │
│  - Angular  │  <── Response ──   │  - Database │
│             │                    │             │
└─────────────┘                    └─────────────┘

Client: Runs in user's browser, displays UI
Server: Runs on remote computer, processes data
```

## 🌐 HTTP Protocol

HTTP (HyperText Transfer Protocol) is the language browsers and servers use to communicate.

### HTTP Request Structure

```
GET /api/users HTTP/1.1          ← Request Line (Method, Path, Version)
Host: api.example.com            ← Headers
Content-Type: application/json
Authorization: Bearer token123

{"name": "John"}                 ← Body (optional)
```

### HTTP Response Structure

```
HTTP/1.1 200 OK                  ← Status Line (Version, Code, Message)
Content-Type: application/json   ← Headers
Content-Length: 45

{"id": 1, "name": "John"}        ← Body
```

## 📬 HTTP Methods

Different methods for different actions:

| Method | Purpose | Has Body? | Example |
|--------|---------|-----------|---------|
| GET | Retrieve data | No | Get list of users |
| POST | Create new data | Yes | Create new user |
| PUT | Replace data | Yes | Update entire user |
| PATCH | Partial update | Yes | Update user's email |
| DELETE | Remove data | Usually No | Delete a user |

### Examples

```javascript
// GET - Retrieve users
fetch('/api/users')

// POST - Create user
fetch('/api/users', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ name: 'John', email: 'john@example.com' })
})

// PUT - Replace user
fetch('/api/users/123', {
  method: 'PUT',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ name: 'John Updated', email: 'new@example.com' })
})

// DELETE - Remove user
fetch('/api/users/123', { method: 'DELETE' })
```

## 📊 HTTP Status Codes

Status codes tell you what happened:

### 2xx - Success ✅

| Code | Meaning | When Used |
|------|---------|-----------|
| 200 | OK | Request succeeded |
| 201 | Created | New resource created |
| 204 | No Content | Success, nothing to return |

### 3xx - Redirection 🔄

| Code | Meaning | When Used |
|------|---------|-----------|
| 301 | Moved Permanently | URL changed forever |
| 302 | Found | Temporary redirect |
| 304 | Not Modified | Use cached version |

### 4xx - Client Error ❌

| Code | Meaning | When Used |
|------|---------|-----------|
| 400 | Bad Request | Invalid data sent |
| 401 | Unauthorized | Not logged in |
| 403 | Forbidden | Logged in but not allowed |
| 404 | Not Found | Resource doesn't exist |
| 422 | Unprocessable Entity | Validation failed |

### 5xx - Server Error 💥

| Code | Meaning | When Used |
|------|---------|-----------|
| 500 | Internal Server Error | Server crashed |
| 502 | Bad Gateway | Proxy/gateway issue |
| 503 | Service Unavailable | Server overloaded |

## 🔗 URLs and Routes

### URL Structure

```
https://api.example.com:443/api/users/123?active=true&sort=name#section1
└─┬─┘   └──────┬──────┘└┬┘└─────┬─────┘└────────┬────────┘└───┬───┘
scheme       host     port    path         query string    fragment
```

### RESTful URL Design

```
/api/users              GET    → List all users
/api/users              POST   → Create user
/api/users/123          GET    → Get user 123
/api/users/123          PUT    → Update user 123
/api/users/123          DELETE → Delete user 123
/api/users/123/orders   GET    → Get orders for user 123
```

### Query Parameters

```javascript
// Filter and sort
GET /api/users?role=admin&sort=name&order=asc

// Pagination
GET /api/users?page=2&limit=10

// Search
GET /api/users?search=john
```

## 📦 Request & Response Headers

### Common Request Headers

```javascript
{
  'Content-Type': 'application/json',     // What format is the body?
  'Accept': 'application/json',           // What format do I want back?
  'Authorization': 'Bearer token123',     // Who am I?
  'User-Agent': 'Mozilla/5.0...',         // What browser?
  'Origin': 'http://localhost:3000'       // Where did request come from?
}
```

### Common Response Headers

```javascript
{
  'Content-Type': 'application/json',     // What format is the body?
  'Content-Length': '1234',               // How big is the response?
  'Cache-Control': 'max-age=3600',        // How long to cache?
  'Access-Control-Allow-Origin': '*'      // CORS - who can access?
}
```

## 🔒 CORS (Cross-Origin Resource Sharing)

CORS controls which websites can access your API.

### The Problem

```
Frontend: http://localhost:3000
Backend:  http://localhost:5000

Browser: "These are different origins! I'll block this request
         unless the server says it's OK."
```

### The Solution

Server must include CORS headers:

```javascript
// In Express
import cors from 'cors';

app.use(cors({
  origin: 'http://localhost:3000',  // Allow this origin
  credentials: true                  // Allow cookies
}));
```

### What You Saw Earlier

```
Access to fetch at 'https://...railway.app/api/users/login' 
from origin 'http://localhost:5173' has been blocked by CORS policy
```

This meant: "The server didn't say localhost:5173 is allowed to access it."

## 🔄 Request-Response Cycle in Your App

### Your School Scheduling System

```
┌─────────────────────┐         ┌─────────────────────┐
│   FRONTEND          │         │   BACKEND           │
│   (React + Vite)    │         │   (Express + Node)  │
│   localhost:5173    │         │   localhost:5000    │
│                     │         │                     │
│  Login.jsx          │         │  userRoutes.js      │
│    ↓                │         │    ↓                │
│  fetch('/api/       │ ──────> │  router.post(       │
│    users/login',    │         │    '/login',        │
│    {email, pass})   │         │    controller)      │
│                     │         │    ↓                │
│                     │         │  userController.js  │
│                     │         │    ↓                │
│                     │         │  MongoDB            │
│                     │         │    ↓                │
│  setUser(data)      │ <────── │  res.json({user})   │
│  navigate('/dash')  │         │                     │
└─────────────────────┘         └─────────────────────┘
```

### Code Flow Example

```javascript
// 1. FRONTEND: Login.jsx
const handleLogin = async () => {
  const response = await fetch(`${API_URL}/api/users/login`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ email, password })
  });
  const data = await response.json();
  // Handle response...
};

// 2. BACKEND: routes/userRoutes.js
router.post('/login', userController.login);

// 3. BACKEND: controllers/userController.js
export const login = async (req, res) => {
  const { email, password } = req.body;
  
  // Find user in database
  const user = await User.findOne({ email });
  
  // Check password
  if (!user || !await bcrypt.compare(password, user.password)) {
    return res.status(401).json({ message: 'Invalid credentials' });
  }
  
  // Send response
  res.json({ user, token: generateToken(user._id) });
};
```

## 🎯 Summary

- **Client** (browser) sends requests, **Server** processes and responds
- **HTTP methods:** GET (read), POST (create), PUT (update), DELETE (remove)
- **Status codes:** 2xx success, 4xx client error, 5xx server error
- **CORS** controls which origins can access your API
- **RESTful URLs** follow a predictable pattern
- Use **DevTools Network tab** or **Postman** to debug API calls
